# 接口能力验证报告

> 全接口实测（2026-09-16 盘中）+ 实时能力评估。命令：标准 7709 / MAC 7709 / 扩展 7727 / 7615 F10+ICFQS。

## 一、总览

- **全接口实测：144/144 通过**（标准 + MAC + 扩展 + F10/AltF10 + ICFQS + 派生）。
- 复现：`python scripts/verify_all.py`（`--group MAC` 可分组，`--json` 输出明细）。
- **实时能力：合格**（见下）。

## 三、验证中发现并修复的问题

| 问题 | 根因 | 修复 |
| --- | --- | --- |
| `get_tick_charts`（0x123E）报 `hour must be in 0..23` / 越界 | 解析规模用 `count×page_size`，实为 `total` 条紧凑排列；盘中当日含越界填充分钟 | 按 `total` 解析、按分钟回绕切分日、跳过越界分钟 |
| `get_minute_aux`（0x051b）**同连接重复调用超时** | 帧长度字段应为 `payload+2` | 长度改为 `payload+2`（重复调用稳定 15–28ms） |
| 扩展行情 `get_markets` / `get_instrument_info` 连接被关闭 | 扩展行情（7727）需**先登录**（`0x2454`） | `ExTdxClient.connect` 增加扩展登录 |
| 服务端主动推送帧导致后续请求错位 | 残留帧未清理 | `TdxConnection.execute` 发送前 `_drain_pending()` 清空缓冲区 |
| `security_list`（0x044d）**同连接重复调用超时** | 用了旧版 `0x0450` 6 字节短包、长度字段错误 | 改用 `0x044d` + `<HIII>`（market/start/count/0）、长度 `payload+2` |
| `sparkline`（0x0fd1）**同连接重复调用超时** | 该命令在单条 TCP 连接上仅响应一次 | `get_sparkline` 每次调用前重建连接（同步+异步） |
| ICFQS 龙虎榜/复盘 **HTTP 503** | 这两个入口部署在 `hot.icfqs.com`，客户端却走默认网关 | `IcfqsClient` 按入口自动选网关（hot/默认） |

修复后全量复测：**100/100 通过**；重复调用稳定；离线单测 **200 passed**。

## 四、已知遗留

- 部分服务器不服务某些新命令（如个别主机对某些命令无响应）；取数命令走 `_execute_std` 自动回退全功能主机。
- L2（逐笔委托/十档）、完整历史 tick/分时：免费协议不提供。
- `0x0fd1` 的"单连接仅响应一次"是服务端行为，已由客户端重连规避（每次调用多一次 TCP 建连）。

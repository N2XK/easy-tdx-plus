# 数据语义与存储

`easy-tdx-plus` 同时提供服务端原始数据和客户端派生数据。为了避免把推导结果误当成
服务端口径，返回的 `DataFrame` 会在 `attrs["provenance"]` 中附带来源、时间点和计算方法：

```python
df = client.get_history_fund_flow(Market.SH, "600519", 0, 20)
print(df.attrs["provenance"])
# {'source': '7709.history_transactions', 'is_approximate': True, ...}
```

需要回测安全口径时可以开启严格模式：

```python
# 不允许用最新股本回填历史换手率/市值
df = client.get_basic_daily(
    Market.SH, "600519", 20200101, 20201231,
    float_shares=..., total_shares=..., strict_semantics=True,
)

# 不允许在服务器缺少历史资金流向时按逐笔金额估算
df = client.get_history_fund_flow(
    Market.SH, "600519", 0, 100, strict_semantics=True,
)
```

严格模式无法保证数据可用时会抛出 `TdxSemanticError`。默认模式仍保留兼容行为，但应
在研究、回测和审计流程中检查 `df.attrs["provenance"]["is_approximate"]`。

核心包提供可插拔落库接口，不强制安装数据库驱动：

```python
from easy_tdx import ParquetSink

sink = ParquetSink("./warehouse")
sink.write("daily_bars", df, mode="append")
```

`DuckDBSink` 需要 `pip install "easy-tdx-plus[duckdb]"`；ClickHouse 通过注入具备
`insert_df(table, dataframe)` 方法的客户端使用。sink 会将 provenance 展开为 `_meta_*`
列，便于查询数据来源和 schema 版本。计划任务、checkpoint、交易日历和多进程协调应放在
上层采集服务中，核心库只负责获取、验证和写入批次。
